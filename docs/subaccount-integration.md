# 補助科目・補助元帳 統合改修報告

調査・実装日：2026年10月13日

## 実装内容

- 勘定科目の補助入力設定：不要／任意／必須。未設定は任意として扱い、既存科目を一括更新しない。
- 相手科目への支援設定：選択名の提案／相手科目の残高候補／提案しない。未設定は提案しない。
- 仕訳明細の補助科目名は自由入力。事前登録不要。新規入力は前後空白を除去し、300文字まで。
- 自由入力コンボボックス、250msの入力待ち、サーバー側候補検索、候補最大50件。
- `*` はSQL LIKEのワイルドカードに変換。`%`、`_`、`[`、`~`はエスケープし、値はパラメータ化する。`*`を含む検索条件は保存名と分離し、未選択の検索条件での保存を拒否する。
- 相手側設定による提案は候補ボタンで表示し、利用者が選択した場合だけ反映する。単一候補でも自動確定しない。手入力を自動上書きしない。複合仕訳は反対側の候補を提示し、循環転記しない。
- 補助元帳・残高メニュー：会社・年度・開始日・終了日は既存の選択を利用。科目・名前の部分一致・残高あり／全件の絞り込みに対応。
- 名前クリックで補助元帳へ移動。日付・仕訳番号・科目・補助名・摘要・借貸・残高を表示。残高一覧は50件、元帳は200件単位でページングする。
- CSV取込・出力、仕訳詳細、仕訳帳の名前検索も文字列名に対応。

## 保存構造とDB変更

明細の保存先は既存の`dbo.lines.data`（NVARCHAR(MAX) JSON）内の`subaccount_name`。科目設定は既存の`dbo.accounts.data`内の`subaccount_input`、`subaccount_assist`。

SQL Serverには次の追加だけを実施した。

|対象|追加内容|
|---|---|
|dbo.lines|`search_account_id`：JSONの科目IDを参照するNVARCHAR(64)計算列|
|dbo.lines|`subaccount_name`：JSONの補助名を参照するNVARCHAR(300)計算列|
|dbo.lines|`idx_lines_subaccount_search`：会社・科目・仕訳IDのインデックス|
|dbo.lines|`idx_lines_subaccount_name`：会社・科目・補助名、仕訳IDを含むインデックス|

計算列は保存値を重複管理せず既存JSONから値を導出する。新しいマスタ・残高・元帳テーブルは作成していない。移行スクリプトは再実行可能。SQLエクスポーターは計算列をエクスポート対象の実データ列から除外する。空DBからセットアップする際は`01-create-tables.sql`に加えて`03-subaccount-search-index.sql`を実行する。

既存9テーブルの全IDとJSONを追加前後でSHA-256比較し、一致を確認した。過去明細・年度・旧マスタ・監査ログの一括書換えは実施していない。

## 旧補助科目・預り金との関係

既存の`subaccount_id`は保持する。文字列名が保存されている場合はその値を優先し、未保存の場合は同じ会社・科目の旧`subaccounts`から名前を解決する。明示的な空文字は「補助科目なし」として扱う。

旧マスタの画面・データ・APIは互換性のため保持した。新しい仕訳入力でマスタ登録を要求しない。旧明細に補助名を一括転記するデータ移行は不要。

預り金専用補助簿の画面・テーブル・専用処理は調査範囲で見つからなかった。預り金／源泉所得税・住民税等は共通の自由入力・補助集計で扱う。検証用預り金仕訳で貸方通常残高の集計を確認した。既存全データは不変であり、専用補助簿からの自動移行は行っていない。

## 集計方法

SQL Server上で会社、科目、仕訳状態ACTIVE、現行明細版、日付を条件としてGROUP BY・SUMを行う。

- BS科目：表示開始日以前の累積と当年度OPENINGを期首に含める。
- PL科目：当年度開始日以降かつ表示開始日以前の発生額を期首に含める。
- 当年度OPENINGは通常発生額・元帳の取引行から除外する。
- 繰越利益剰余金の過年度損益は既存集計と同じ計算で「補助科目なし」に加える。
- 期首差額の専用設定は従来どおり科目単位であり、補助未配分分は「補助科目なし」に含める。
- 残高＝期首＋借方－貸方。表示は科目の通常残高方向に合わせ、貸方通常科目では符号を反転する。
- 元帳の逐次残高はSQLのウィンドウSUMで求める。ページを跨いでも期間先頭からの累計を使う。
- 残高ゼロや訂正前・取消後の名前は履歴から検索できるが、その旧版・取消額は残高に算入しない。仕訳日より後の履歴名も検索でき、選択を禁止しない。
- 認証ユーザーの会社所有権を確認し、読み取りトランザクション内で集計する。検索のたびに会社全明細をクライアントへ送信しない。

## 検証結果

以下は成功した。

- `verify-subaccounts.js`：自由名、空白、不要／任意／必須、トリム、SQL特殊文字、CSV往復、旧ID、訂正・論理削除、預り金、複数年度、BS・PL・試算表。
- `verify-subaccounts.js --sql`：SQL Serverの一時テーブル上で複数会社・年度・期間途中の期首・逐次残高・ゼロ履歴・ワイルドカードを検証。既存DBの53科目・年度を年度開始と期間途中の2条件、計106条件で既存元帳集計と照合。
- `verify-subaccount-ui.js`：実際の配信JSをVM実行し、提案の選択・変更・削除、手入力保護、複合候補、提案なし、残高検索の会社・科目・日付、検索と保存値の分離を検証。
- 既存の`verify-opening.js`、`verify-company-archive.js`、`verify-tax-order.js`、`verify-export.js`：期首、繰越、財務集計、復元、税区分順序、認証・ログアウトの回帰検証。
- JavaScript構文検査、Git差分の空白検査。
- 計算列追加後のSQLバックアップを一時ファイルへ出力し、全9テーブルの出力成功を確認。既存のSQLファイルは変更していない。

既存DBへの仕訳登録や編集はテストしていない。DB集計検証は一時テーブルと既存データの読み取りを利用した。

## 未実装・未検証と運用上の留意点

- 指定どおり、伝票別消込・分割決済・消込自動仕訳は実装していない。
- 補助単位の期首残高設定は今回追加していない。科目単位の既存期首設定を保持する。
- 実ブラウザーでの目視・モバイル操作、10万行での負荷試験は未実施。配信JSの入力処理はVMで検証した。
- 通常の会社読込は既存どおり全会社データ取得であり、今回の補助検索・集計APIだけを件数制限した。既存画面全体のページング改修は行っていない。
- 旧IDだけの明細は、旧マスタ名の変更に伴い表示名も変わる既存方式を維持する。新規文字列名は明細に保存した名前を使う。
- 「不要」に変更済みの科目でも、過去明細の変更されていない補助名は保持可能。「必須」の科目を保存し直す場合は空白を許可しない。期首仕訳と自動税明細は既存処理維持のため入力必須チェック対象外。
- アプリへの反映にはNodeサーバーの再起動が必要。Gitコミット・Pushは今回実行していない。

## 将来の消込機能

仕訳ID、明細ID、仕訳番号、明細版管理を維持している。将来は会社IDと明細IDを参照する消込テーブルを追加し、伝票番号・予定日・決済割当・分割／一括消込・自動仕訳の関連を別管理できる。補助名だけを伝票・消込の識別キーとして使用しない。訂正時は旧明細ID・新明細IDとの関連を明示して扱う。
