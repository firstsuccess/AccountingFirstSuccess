# 会社・伝票・明細の採番変更

## 採番仕様

- 新規会社：DB全体のC番号の最大値＋1。`C000000001`形式。アーカイブ会社も含む。トランザクション内の更新・範囲ロックで採番とINSERTを一体化する。
- 自動伝票番号：会社ごとの`J000000001`形式。削除済み伝票の番号を再利用しない。CSVの指定番号は維持し、J番号を指定した場合は次番号も進める。
- 明細の実際の内部ID：`C000000001-J000000001-R00001-00001`。34文字。版・行番号はそれぞれ5桁で、1～99999。既存NVARCHAR(64)に収まる。
- 修正時は伝票番号を保持して版を進め、旧明細を残す。自動税明細も行番号を持ち、税計算元の明細IDを同時に付け替える。
- 表示・CSV・JSONのline_idは同じ実明細IDを使用する。行番号自体は`line_number`でも保持する。
- 既存のUUID会社は未移行でも読取・編集可能。UUID会社の明細IDは60文字（伝票番号が標準J番号の場合）。任意のCSV伝票番号との合計が64文字を超える場合は登録を拒否する。

## 移行コマンド

サービスを停止した状態で、C:\accountingから実行する。

```powershell
# デフォルトは全変更をロールバックするリハーサル
node --env-file=.env scripts/migrate-identifiers.js

# 検証後にコミットする本適用
node --env-file=.env scripts/migrate-identifiers.js --apply
```

スクリプトは新会社IDが存在する場合・旧会社がない場合に拒否し、二重移行しない。全テーブルの排他ロック、トランザクション、Git対象外の物理JSONバックアップを使用する。必要な保護トリガーだけを同一トランザクション内で一時停止し、確定前に再有効化する。途中の異常時はトリガー状態を含めてロールバックする。

保存処理で新規仕訳、訂正、削除、古いversionによる更新拒否、新会社C000000002の採番も検証する。これらの検証用データはSAVEPOINTまでロールバックし、運用データには残さない。

## バックアップと注意

- `backups/pre-identifier-migration.sql`：移行前SQLデータバックアップ。空の復元先DBへの復元用。
- `backups/identifier-*.json`：各リハーサル・本適用直前の全9テーブルと番号対応表。
- backupsディレクトリーはGit対象外。認証情報は含めないが会計データを含むため非公開で管理する。
- 移行前のCSVは旧company_id・伝票番号を含む。移行後は新しいCSVを再出力して使う。旧CSVをそのまま再取込しない。
- 既存ブラウザーは会社を再選択／再読込する。URL・外部連携で旧会社IDを指定している場合は更新する。
- SQLサンプル`02-data-PARTIAL.sql`は今回自動更新しない。現在の運用DBと同じデータを配布する場合は、別途確認して再出力する。
